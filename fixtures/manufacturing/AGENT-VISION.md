# Software manufacturing inputs vision

Provide reproducible TypeScript-authored schema7 printer data and explicit planar intent for native-section compilation, emitted-program replay, durable artifact and fresh-process inspection evidence. Required native_shape_error_mm, seam and rectilinear-axis recipe policies are captured with the full intent, separately from XY curve sampling and finish displacement budgets. Directions use build/machine XY, never source/camera coordinates. Profile/recipe revisions identify the cutover; original STEP corpora and configuration/calibration bytes are unchanged. Source-face finishes and content-addressed spatial image inputs remain project-scoped captured data rather than a profile-global recipe flag. Separate printer specification from material/process recipe so another ordinary profile can be authored as data without changing the native planner.

References are software-only unqualified declarations, not commercial machines or calibrated materials. Required process/support policies drive actual retraction/cooling/first-layer/bridge/support software semantics. Complete sparse intent is available as trusted TS and inert JSON with unchanged empty calibration provenance; revised configuration explicitly declares ordinary default cooling fan, no laser synchronization and external E-only retraction. Physical firmware/calibration/printing remain external gates; record hashes, shapes and replay establish no machine qualification.
