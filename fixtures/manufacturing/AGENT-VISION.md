# Software manufacturing inputs vision

Provide reproducible TypeScript-authored printer data and explicit planar intent for native-section compilation, emitted-program replay, durable artifact and fresh-process inspection evidence. Separate printer specification from material/process recipe so another ordinary profile can be authored as data without changing the native planner.

References are deliberately software Cartesian envelopes, not commercial machines or calibrated materials. Diagnostic bodies and complete single-extruder Marlin lifecycles exercise separate contracts; complete sparse intent combines physical-thickness skins, nominal sparse ownership and independently decoded lifecycle/object accounting. Published configuration/calibration records explicitly contain no physical measurements. Physical printing, actual firmware/thermal behavior, collision avoidance and supported-machine qualification require separate evidence; record hashes, component shapes and successful replay do not establish them.
