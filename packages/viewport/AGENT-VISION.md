# Viewport vision

The viewport is a disposable WebGPU geometry and actual-program motion display consumer, independent of React and the native shell. It displays engine-admitted definition meshes through shared occurrence batches, revision-aware source-face picking, native section overlays, and an orthographic inspection camera. Its packed SPLR motion module provides standalone or optional native-scene overlays with layer/event/travel draw-state controls and an explicit unknown-start endpoint. Native BREP, source units, f64 carrier parameters, independently decoded program coordinates, and section computation remain authoritative outside this package; GPU meshes and lines are approximate display only.

The supported display contract is derived multi-instance geometry and bounded actual replay: independently decoded SPLM/SPLS/SPLR bytes, atomic staged scene/section/motion publication, origin-rebased placements, shared active/staged admission and explicit interrupted synchronization with resume. Geometry-only definitions retain authoritative native bounds and source-face identity without fabricated mesh buffers, GPU geometry or picking; mixed and zero-rendered scenes publish atomically. Project persistence, artifact freshness, verification and authoring remain outside the viewport. There is no diagnostic-triangle UI fallback, manufacturing planner, mesh-derived section, WebGL fallback, or per-occurrence duplicate geometry ownership.

An explicitly requested diagnostic dashboard may display decoded SPLT output in its own lazy viewport. This is not an import fallback, native geometry evidence or physical GPU certification; it owns and releases a separate diagnostic device/renderer.

Acceptance requires visible, correctly placed and pickable native objects and independently decoded actual motion on declared physical WebGPU reference machines, including repeated instances, large origins, section/motion coexistence, unknown/coincident travel, draw-state controls, atomic replacement, upload cancellation/resume, and awaited stop/restart/device-loss cleanup. Implementation alone does not establish that hardware gate, native geometry accuracy or machine readiness. Resource counters describe owned display buffers rather than unavailable total-driver-memory measurements.
