# Viewport rules

- Own Three.js scene and GPU resources only. Consume decoded display buffers from `@spiling/protocol`; never invoke Tauri, own native geometry, or synthesize an engine artifact.
- `createGeometryViewport(canvas, onFailure)` admits and initializes a real WebGPU adapter/device before resolving. Pass the probed device to `WebGPURenderer` with `forceWebGL:false`, disable Three's pinned `_getFallback` hook before initialization, and check the backend. Review that integration when updating Three; never substitute WebGL or invented geometry.
- `createDiagnosticViewport` is a separate explicit SPLT diagnostic surface retained by the operation dashboard, created only when requested. It consumes independently decoded engine bytes and has the same strict WebGPU/no-fallback and awaited disposal requirements; it never substitutes for native geometry. Diagnostic device/renderer overhead is not included in native `bufferUsage`.
- `beginScene` pauses picking and clears selection; changed revisions also clear sections. Upload decoded chunks sequentially, then `commitScene` validates complete definition/occurrence/source-face associations and publishes only after rendering. `GeometryDisplayDefinition` associates the generated `DefinitionRecord` with its generated `FaceIndexRow` page results; it is not a native domain model. `hasDefinition` identifies reusable immutable session/artifact buffers. `updateOccurrences` reuses those buffers without transfer or tessellation.
- Own one shared mesh `BufferGeometry` per definition/chunk and occurrence `InstancedMesh` batches. Source-face picking maps CPU raycaster instance/triangle indices to the current generated `FaceRef`; never send approximate GPU hit coordinates as native measurements. Face highlights use shared attributes/index groups, not copied vertices or retessellation. Borrowed decoded buffers and metadata must remain immutable for their entire ownership lifetime.
- Admission accounts for combined active/staged retained raw buffers, GPU attributes, CPU/GPU instance matrices, and CPU/GPU section display buffers under the generated 128 MiB cap. `bufferUsage` reports these owned buffers, not total driver memory or renderer-private allocations. Enforce admission before allocation; at most one upload/update is admitted, with a frame yield and awaited render/GPU completion, not an unbounded upload queue.
- Rebase f64 native coordinates about the scene-bounds center before f32 GPU conversion. Instance translation is `R*chunk_origin+t-display_origin`. Packed section lines use relative f64 points plus `plane_origin-display_origin`; native loop data remain borrowed f64. Orbit/pan/zoom, front/isometric presets, fit, and resize request coalesced renders without an idle animation loop.
- `discardScene` releases staging while retaining the old display; a mismatched engine/display revision remains noninteractive until a successful resumed commit. `showSection` stages ordered chunks and atomically publishes the final complete overlay; `null` is permitted only for an empty section. `discardSection` drops only staging and retains the previous overlay. Scene revision changes clear both overlays immediately.
- Device loss, uncaptured GPU errors, and render failures report one fatal failure; synchronization/resource/stale-input errors are explicit exceptions, never fallback success. `dispose` disconnects interaction/resize, awaits uploads/renders, releases shared resources once, disposes the renderer, and destroys the owned device. Concurrent disposal returns the same completion; callers must await teardown before replacement.
- `check` typechecks. Real desktop acceptance must exercise placed/repeated objects, source-face picks, sections, large origins, transfer pause/resume, resize, loss diagnostics, and cleanup on declared hardware. No source-text wiring assertions or synthetic canvas substitute for that surface evidence; software GPU runs are diagnostics only.
- Preserve OSL notices and adjacent JSON licensing sidecars.
