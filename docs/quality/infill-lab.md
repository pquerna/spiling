# Interior construction research

[`tools/infill-lab`](../../tools/infill-lab) is offline Linux research tooling. It proposes inert process edits through the ordinary CLI, compiles with the engine, saves and independently replays actual emitted programs. The production checked SPLR decoder supplies the deposition roads. It does not own a planner, kernel, project writer or workbench physics engine.

Remote CPU/CUDA comparisons over frozen systems use the isolated [evaluator container](../../tools/infill-lab/remote/README.md).

## Run and resume

Install `uv` and the repository's pinned Node toolchain. Use `pnpm build:native` to build matching engine/CLI binaries under the normal [resource discipline](development.md), then copy them into a private, immutable experiment bin directory. Never replace shared build outputs during a campaign. The optional research dependencies install only through `infill:lab`, outside product builds and distributions. `uv.lock` freezes Python dependencies; `SPILING_UV` can select a local uv executable.

```sh
pnpm infill:lab test
systemd-run --user --wait --pipe --collect \
  --property=WorkingDirectory="$PWD" \
  --property=MemoryMax=12G --property=MemorySwapMax=0 --property=TasksMax=512 \
  /usr/bin/env OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 RAYON_NUM_THREADS=1 \
  pnpm infill:lab study --output .cache/interior-study --bin-dir .cache/interior-bin \
  --limit 48 --seconds 900 --trial-seconds 120
pnpm infill:lab report --campaign .cache/interior-study/campaigns/CAMPAIGN_ID \
  --output .cache/interior-report
```

A fixed larger-interior panel is available with `pnpm infill:lab sweep run --output NEW_DIR --bin-dir FROZEN_BIN --seconds 7200 --trial-seconds 900`, under the same external memory/tasks bounds. `sweep report --study-root DIR --output REPORT_DIR` regenerates the standalone interactive chart, PNG and full results. This panel compares production alternating/aligned rectilinear and Grid density sweeps against solid using finite actual-interior coupons from six original source shapes. Its frozen comparison panel stays unchanged. Explicit candidate JSONL may additionally select the production `web_roof` pattern for its admitted constant-section analytic-extrusion lane; the [Cathedral infill contract](../protocol/manufacturing.md#web-and-roof-infill) owns its limits. This availability does not close the element-convergence gate or establish a mechanical advantage. Select resources and deadlines from the measured machine and trial costs; a large body can use substantially more memory than the example above.

`campaign capture --candidates QUEUE.jsonl` also accepts an explicit `roof_spacing_mm` for Cathedral. The current study grammar bounds it to 0.45–7.5 mm, matching the captured 0.45 mm bead and 10 mm bridge-span recipe; omission retains Auto. The engine independently validates the entire recipe and construction. Other patterns reject that parameter. Keep changed spacing in a separate, predeclared panel rather than silently changing frozen controls.

New native captures remove only their owned source/intent copies after save, before opening the PTAC in a new engine for fresh verification, actual replay and export. Caller-owned frozen specimens remain unchanged. Freshly exported program, plan, provenance and verification bytes must match the compiled four-file export; retained per-file hashes bind that equality. `Native.reopen` additionally compares saved-return replay bytes and exported program bytes. A fresh process while external source copies remain present is not source-independent evidence. Historical captures need an explicit source-absent return check before claiming that stronger workflow; do not rewrite their original inputs or mechanical identities.

`python tools/infill-lab/vault_report.py SIX_SHAPE_CAPTURE OUTPUT` audits the complete native panel and exact artifact hashes before drawing matched whole-object material/motion plots and actual-program sections. Include one admitted solid control and matching Grid settings per source. Refusals remain in the result; incomplete panels fail. Its time value is a decoded-motion lower bound, excluding thermal waits, acceleration and firmware. It deliberately emits no mechanical frontier or strength score. Mid-height interior compression cannot qualify roof, floor or joint reinforcement: those changes require an independently converged fixture that exercises their load transfer, followed by whole-part and physical validation.

`vault_search.py` provides a separate, bounded parameter-search cohort: `propose --round 0 --output ROUND` emits ten Vault seeds plus seven fixed Rectilinear/Grid/solid controls; rounds 1–3 take `--history ARCHIVE` and propose ten local mutations each; round 4 emits ten exploration points. Feed each `queue.jsonl` through ordinary `campaign capture --specimens cube48`. Freeze a context with `campaign context`, then use `vault_search.py pack --capture CAPTURE --context CONTEXT --output INPUTS` and `campaign dispatch --backend vault`. `collect --input INPUTS --results RESULTS --proposals ROUND/proposals.json --output ARCHIVE [--history PREVIOUS]` checks native/input identities, numerical residuals and container cleanup before extending the archive. Changed fixture/material/judge/image cohorts cannot be pooled. `pack --max-z 1` coalesces only identical geometry spans for screening; smaller `--max-z`, larger `--divisions`, and shifted/wider crops create separate validation cohorts. `--width`, `--depth` and `--shift` freeze the physical crop; use a smaller crop for exploratory latency and preserve larger crops as separate checks. `--selection IDS.json` retains an explicit subset for those paired checks. `vault_search_report.py --archive ARCHIVE --captures CAPTURE... --output REPORT` audits the native closure and renders the material/motion comparison and actual-road gallery.

`vault_pair.py prepare --captures CAPTURE... --ids PARENT CHILD --output PAIR` freezes two admitted captures with identical source and producer into a separately audited native closure. `vault_pair.py pack --capture PAIR --context CONTEXT --output INPUTS --shift 0.3 --divisions 2` creates an independent physical validation fixture; dispatch with the existing `vault` backend, then `vault_pair.py collect --capture PAIR --input INPUTS --results RESULTS --output REPORT`. The comparison retains each direction, zero/disconnected directions and incomplete results; there is no minimum useful effect. Repeat unshifted/refined and shifted/wider pairs in distinct directories rather than pooling them into the primary search. Smaller requested density may increase actual roof construction and whole-object cost; only decoded deposition establishes the material axis.

`vault_search_run.py --output STUDY --bin-dir FROZEN_BIN --context FROZEN_CONTEXT --workers WORKERS.json --solver superlu_mmd` executes/resumes all five rounds inside external native memory/tasks/time bounds. `WORKERS.json` names `hosts`, distinct already-provisioned `roof_prefixes` and `core_prefixes`, `memory_gib`, `cpus` and `blas_threads`. The driver installs nothing. It admits a common prefix count from live host memory/core headroom, runs disjoint shards, freezes controller/configuration identity, preserves raw failures, and records paired six-response archives. Cohorts bind the selected core solver as well as physical inputs and image; returned solver identity must agree. Solver comparisons and changed physical crops remain separate cohorts. A complete panel with no scored cases retains failed rows and an empty frontier, rather than becoming a collection error or an implicit success. Do not mutate a running evaluator image or input. Later rounds copy the exact seed specimen bytes and their manifests; re-exporting the same geometry is insufficient because exporter process state can change source identity. A pre-existing different source refuses rather than being overwritten. Parameter count and distinct emitted-program count stay separate in reports.

The roof-patch judge selects an explicit existing linear solver (`pack --solver`), retaining unchanged residual/reaction/energy checks. Small difficult coupons can use direct factorization rather than long iterative preconditioning. The judge includes actual deposited skins and corbels in a finite interior crop; it uses the existing nominal-footprint quadratic elasticity and weak-Z material assumption. It excludes side walls and retains no artificial ties. Whole-object replay dose and decoded motion remain the cost axes. `core-pack` supplies a broad mid-body XYZ coupon through the existing independent quadratic backend; `join-core --roof ROOF_ARCHIVE --input CORE_INPUTS --results CORE_RESULTS --output ARCHIVE [--history PREVIOUS]` binds both fixtures by actual-road identity. Keep roof-only histories separate when collecting the next roof batch. A small roof crop can give identical responses for different base webs; the core fixture exposes that omitted load path. Each fixture/direction is retained separately in the Pareto archive; there is no minimum percentage improvement. Mesh-convergence targets concern absolute accuracy, not permission to explore or a minimum useful gain. Small paired improvements remain provisional: refine parent/child together, check shifted/wider patches and held-out sources/loads, and retest accumulated changes. Repeated deterministic solves alone do not establish discretization accuracy. Roof-patch compression is neither roof bending qualification nor whole-part/physical strength; experimental findings do not change production defaults automatically.

Use `pnpm infill:lab summary --study-root .cache/interior-study --output .cache/interior-report` for paired control comparisons across mesh, phase, shape and material scenarios. It refuses to pool changed judge/producer identities, preserves cost increases and keeps budget-feasible alternatives separate from equal-density comparisons.

### Perforated web and pier-rib ablation

`cathedral.py seeds --output SEEDS` emits four native Cathedral recipes: automatic construction, explicit capped windows, explicit vertical pier ribs and their combination. Feed `SEEDS/candidates.jsonl` through ordinary `campaign capture --specimens cube48` with coherent frozen binaries and external native bounds. The existing production contract independently admits every window, retained pier/landing/roof-root corridor and merged flange; this is not a renderer-only lattice. `web_opening` carries the five explicit bottom/height/width/cap/pier values and `pier_rib_depth_mm` carries the bounded vertical flange reach. These remain offline research controls; they do not add more workbench pattern choices or change defaults.

Freeze the normal evaluator context/image, then run `cathedral.py pack --capture CAPTURE --context CONTEXT --output INPUTS --solver superlu_mmd` and `campaign dispatch --backend vault`. The finite source-frame crop is frozen from the flat control's actual roads and includes a complete window, its cap and two real piers. It is neither a constant-footprint substitution nor a whole-part model. Two directional compression cases and an out-of-plane cantilever share one mesh/material assembly per connected component. The cantilever clamps all displacement components on its lower-Z material patch and imposes transverse-Y displacement on the upper patch; the other upper components remain free. Slender-beam and proper-axis-rotation controls check that fixture separately. Shear, nonlinear collapse, buckling, roof bending and physical material/bond laws remain unqualified.

`--divisions 2/4/8` and explicit solver selection create separate immutable numerical cohorts. Optional `--cap-segments 4/8/16/32` selects nested inscribed capsule polygons;32 remains the unchanged reference default. Every mesh records the quarter-segment count and maximum radial chord error `radius × (1 − cos(π/(4 × count)))`. Lower counts are a separately identified geometry-approximation study, not an accuracy waiver; compare complete responses with retained fine controls before ranking and preserve unresolved windows as unknown. Direct and iterative solves retain the same residual, reaction and energy checks; compare their paired responses before treating a runtime improvement as equivalent. The global footprint arrangement remains bounded and can become expensive for changing layers; preserve meshing/solver refusals rather than dropping cap layers or inventing ties. `cathedral.py collect --inputs INPUTS --results RESULTS --image IMAGE_JSON --output ARCHIVE_JSON` rejects changed inputs/judges/scenarios/images, failed numerical checks and unremoved containers. Timeouts remain unknown responses, never zero stiffness. Component-wise material/motion/response Pareto retention has no minimum effect-size threshold. This four-way ablation cannot establish superiority to tuned Grid/solid controls, an adaptive-search algorithm or the global infill frontier.

Explicit `pack --mesh-method tetgen` replaces only the accepted affine prism mesh's interior tetrahedralization. The optional [external research image](../../tools/infill-lab/remote/README.md#retained-boundary-volume-remeshing) supplies pinned TetGen 1.6. Original boundary coordinates/IDs and the complete oriented triangle inventory must remain exactly identical; every shared internal face must cancel with opposite orientation, all tetrahedra must have finite positive volume after orientation normalization, and total volume/component count must agree. These checks consume the existing source mesh's material admission rather than re-rounding its footprint. They do not admit new CAD or physical bonds. Only complete positive-area faces share displacement nodes; point/edge contacts remain separate. Raw tetrahedra use the same quadratic basis, quadrature, material and physical solve gates as the preserved prism subdivision. Compare paired controls and separate refinement cohorts before interpreting response differences; no automatic mesher or solver fallback is allowed.

`cathedral.py propose --history ARCHIVE --round 1 --output ROUND` requires all four scored ablations before emitting six parameter interventions plus solid, retaining the earlier queue and parent/hypothesis records. Round2 emits six distinct neighbors of measured Pareto parents; it holds source, base density and fixture fixed. Capture the complete queue using the same frozen specimen bytes and ordinary native closure reuse, then pack/dispatch and `collect --proposals ROUND/proposals.json`. Every intervention is still independently admitted by the engine. Failed mechanics remain unknown and cannot become adaptive parents. Solid pays its complete deposited material/motion. Declare `pack --bay-half-width 2.25` for the complete queue before ranking deeper flanges; packing refuses a flange tip outside its fixed crop. The bounded descendant grammar stops at1.8mm reach so the declared2.25mm margin contains complete nominal caps. The original narrow bay remains a different physical fixture. Optional `pack --max-xy 1 --max-z .4` creates a separate explicit span-refinement cohort. These bounded descendants exercise existing windows/vertical pier flanges, not the unimplemented broader rib/fold grammar; a finite web selected around a Vault bay is not a fair global Grid/pattern-phase benchmark.

`cathedral_report.py --capture CAPTURE --archive ARCHIVE_JSON --output REPORT` audits the complete native closure and renders nominal footprint sections, actual layers and the local elastic comparison. Galleries retain the declared numerical crop and add separate complete-height sections, including diagonal roads and their rounded caps. All outer walls, skins, webs, ribs and roof work remain charged to complete decoded object dose/motion; the numerical response describes only the declared cut bay. Never label the geometric mean of those local stiffness ratios as strength or promote a construction from an unresolved mesh result.

The memory/task values are example externally enforced whole-process bounds, not machine requirements or product worker limits. Select limits from available machine resources, retaining room for concurrent work. The runner requires finite cgroup-v2 memory/tasks limits, executes native trials sequentially and kills its owned process group on deadline/output overflow. No shared Cargo or Git mutation occurs in a trial.

Each campaign freezes evaluator/dependency/producer/intent hashes, material, specimen, mesh, phase, case and seed. Editing them starts another campaign; running again with unchanged inputs resumes the append-only, fsynced trial log. A writer lock prevents two campaign drivers. `--controls-only` stops after an explicit comparison queue, including on resume, rather than continuing with mutations. Failed/refused/timed-out trials remain visible. Successful native artifacts have checked file hashes; interrupted incomplete cache entries fail rather than becoming successful reused data. Candidate JSONL can supply an explicit comparison set with `--candidates FILE`; subsequent trials mutate sampled Pareto candidates. This bounded search is not a claim of superiority to random search or a global optimum.

## Evaluator and scoring boundary

`geometry.py` forms local unions of actual nominal XY footprints over each actual physical interval. Retained mesh cells are fully inside those unions. Only face-connected cells share degrees of freedom; a distant bead contact never ties a local gap. Identical footprint masks may be reused after exact XY identity and interval membership checks. A separate inscribed-stadium diagnostic exposes the sensitivity to idealized bead/contact shape.

`--mesh-method prisms` nodes the boundaries of local footprint unions with GEOS, triangulates the resulting shared arrangement and extrudes conforming Wedge1 cells over actual slabs. Ownership is checked on the original arrangement faces and inherited through subdivision; re-rounding refined triangle vertices cannot erase neighboring contacts. Only identical full faces share displacement nodes. Repeated Z sections merge only after identical occupancy is checked over every physical slab. Every face belongs entirely to a local deposited union or lies outside it; straddling faces and hanging internal edges refuse. Outer-edge checks use the declared 1e-9 mm overlay-grid roundoff, never a weld. Mesh volume must retain at least97% and cannot exceed the nominal footprint volume. `--dx`/`--dz` bound element spans and `--divisions 2/4/8` adds repeated conforming planar refinement. This equivalent continuum remains distinct from actual bead dose and physical bond calibration.

The wedge adapter supplies an explicit triangle × line quadrature. The pinned library's default RefWedge rule incorrectly tensors the two triangle coordinates independently, so it is not used. Known mixed moments, analytic force and independent higher-order library assembly protect the adapter. The original uniform-hexahedral model remains available for numerical comparisons. Physical residual/force/energy gates establish an accurate discrete solve, not mesh convergence: slender bead bending can remain too stiff on coarse elements. Treat an unresolved refinement change as screening evidence, never a qualified effect size or a fitness function for promoting a new construction.

`mechanics.py` uses scikit-fem full-integration Hex1/Wedge1 elasticity with SciPy/PyAMG. Assumed homogeneous PLA and perfect nominal bonds predict **elastic stiffness only**, not strength, buckling, crushing, fracture, layer adhesion, sag or physical printability. The general small-study default is isotropic; the larger `sweep` defaults to an explicitly assumed weak-Z ratio0.25. Isotropic and ratio0.5 are sensitivity scenarios, not calibrated PLA properties. `--z-ratio` optionally weakens Z modulus and XZ/YZ shear for an explicitly assumed transversely isotropic sensitivity scenario; reciprocal, positive-definite compliance is checked. Neither scenario is measured layer adhesion. Analytic axial units/energy and the optional independent `oracle.py` CalculiX C3D8 checks qualify the numerical solver, not the material model. CalculiX is externally installed and not distributed with Spiling. A nominal footprint continuum is not a measured deposited bead; its volume stays distinct from the independently verified extrusion dose.

Raw Pareto axes minimize commanded deposited material and feed-based motion time while maximizing stiffness for the declared fixture. Solid-fill and tuned ordinary controls are mandatory comparison inputs. Material uses actual verified object dose; supports are disabled and fixed startup priming remains separate in the raw report. It is constant across the paired comparisons; time includes stationary retraction/recovery but excludes heating, acceleration and firmware delays. A ratio alone cannot hide an absolutely weak result or make solid plastic win without paying for its material/time. Galleries draw actual replayed paths, cut away upper roads for inspection, and show two adjacent physical intervals as nominal footprints. The paired layers distinguish alternating roads from continuous same-layer webs; no ideal lattice replaces the program.

Bending fixture datums and imposed strain bind the unchanged source dimensions, not grid-dependent bounding boxes. `--case compression_envelope` retains three independent directional compression results and scores their minimum; it is not simultaneous hydrostatic pressure. Metric-scaled unit-element quadrature kernels and balanced sparse reductions avoid storing full per-cell basis gradients or repeatedly rescanning an ever-growing matrix. They retain ordinary conforming Hex1/Wedge1 elasticity; direct library assembly on nonuniform cells protects equivalence for isotropic and weak-Z materials. The same mesh/material matrix is assembled once for those loads, with separate boundary conditions, residuals and reactions. Matrix reuse across changed meshes/materials is rejected.

`pnpm infill:lab budget --study-root DIR --bin-dir BIN --specimen holdout --budget-mm3 VOLUME --output NEW.jsonl` proposes Grid densities using at most four actual native cost measurements by default. It sees no stiffness. Row-count quantization means this is bounded budget repair, not exact mass inversion or a guarantee that material cost is monotone. Native refusal stops proposals; no guessed cost licenses another construction. Evaluate the resulting candidate JSONL through the unchanged judge.

The normalized coupon chart uses the geometric mean of candidate/solid directional stiffness with equal source and XYZ weights. Y averages each source's complete verified object-dose/solid ratio; a second view retains normalized motion time. Walls and skins are excluded from coupon mechanics but remain fully charged to material cost. Each point needs a complete frozen panel, one coherent judge/producer/material/discretization scenario and same-source solid references. A completed, witnessed lack of a fixture-spanning component is a valid zero coupon response; a failure, timeout or missing case is never zero. Individual ratios, Z response and the weakest direction remain visible. Lines connect evaluated settings, not qualified interpolated constructions. Wall, skin and regional-interior bridge dose reconcile to verified object dose. Solid remains a costly measured endpoint. This is simulated elastic stiffness, never asserted strength.

## Independent remote campaigns

`pnpm infill:lab campaign capture --output NEW_STUDY --bin-dir FROZEN_BIN` generates original cube, beam, column, panel, through-hole and notched sources, then executes sequential ordinary create/edit/compile/save/fresh-replay/export operations. Standard controls cover multiple actual density settings through solid. Single-interface regional separator and crown recipes are proposals through existing process authority, not an alternate geometric generator. Unsupported constructions retain their native refusal and earn no mechanics score. Two-boundary webs and general topology optimization are not implemented. `--reuse PREVIOUS_STUDY` can copy only checked unchanged uniform captures with identical source, producer binaries, intent and decoder; complete artifact hashes and absence of process edits are mandatory.

`campaign context --output NEW_CONTEXT` assembles an explicit evaluator-only Docker context. `campaign pack --study-root STUDY --context CONTEXT` freezes hashed inert deposition jobs; `--solver`, `--z-ratios`, `--divisions` (1/2/4/8) and `--shifts` declare numerical method, material, conforming planar refinement and cut-position sensitivity panels. `--candidates` selects a frozen subset without importing unrelated native refusals. Remote CPU/RAM defaults follow measured host resources; explicit overrides select a smaller share when independent workers coexist. Combined worker bounds must leave host headroom; `--blas-threads` controls a solver team separately from CPU admission. The container evaluates independent finite XYZ compression with retained physical residual/reaction/energy gates. Its source hashes must match the frozen judge. Remote jobs receive no engine, project mutation API or executable candidate.

Build/copy the exact image through the [remote runbook](../../tools/infill-lab/remote/README.md), then run `campaign dispatch --input STUDY/inputs --output STUDY/remote --hosts USER@HOST1 USER@HOST2 --remote-root /home/USER/src/spiling-eval/COHORT --run-id COHORT`. Each resource prefix processes independent jobs sequentially under a lock and finite deadline, CPU/PID/RAM limits. For additional admitted parallelism use disjoint `--shard-index` / `--shard-count` queues with separate owned prefixes; the same input manifest is retained and collection still requires the complete panel. Select the number of prefixes from live host memory/core availability and measured per-job costs, reserving OS/user headroom; sum their hard memory limits before launch. Native capture and remote mechanics have separate ownership and can overlap. `campaign dispatch --cpu-profile` records Python CPU profiles inside the same bounded container, without host packages or changed solver math; profiling overhead stays separate from decoded product motion cost. Retain failed captures, remote failures, launch receipts and immutable image identity. Reconnect and inspect an uncertain SSH outcome before retrying. Results and scientific plots belong in ignored experiment artifacts; retained research conclusions live outside the public runtime contracts.

Before recommending a construction, repeat promising comparisons with finer cells, shifted mesh phase, material/contact sensitivity and held-out sources/load cases. Separate numerical uncertainty from model uncertainty. A load-specific simulated improvement does not establish a general-purpose interior algorithm. Physical validation requires a captured printer/material cohort and measured stiffness/failure tests; no research ranking grants manufacturing authority.

## Cathedral infill construction campaign

`tools/infill-lab/web_roof_campaign.py` generates original BRepCheck-valid AP214 pressure sources using tooling-only `cadquery-ocp==7.9.3.1` in an isolated Python prefix. With frozen matching engine/CLI binaries, run `PYTHON tools/infill-lab/web_roof_campaign.py --output NEW_DIR --bin-dir FROZEN_BIN --seconds 90` inside the documented native memory/task/time bounds. No dependency is installed into the engine or globally. The default matrix covers round, annular, L/U, narrow-neck, four-hole, thin and diamond footprints at8%/16% base webs. Cone, sphere and shelf probes retain the actual native-import/constant-section refusal stage; they are not expected positives.

Each positive must compile, freshly verify, save, lose external source/intent copies, reopen in a new engine, freshly replay/export and retain byte-identical four-file output. Binary hashes freeze the producer through the run. Candidate failures make the command fail. `--roof-spacing`, `--width`, `--walls`, `--layer-height`, `--fractions` and `--cases` support physical-parameter pressure tests; `--pattern fine` or `grid` supplies ordinary-pattern controls to locate shared constructor failures; `--generate-only` retains original sources without claiming slicing. Output contains source/producer identities, diagnostics, actual decoded roads and per-case material/time measurements. `PYTHON tools/infill-lab/web_roof_report.py CAMPAIGN_DIR` renders actual emitted XY layers and vertical nominal-bead sections with tooling-only numpy/matplotlib. It requires accepted journeys and fresh verified receipts, and distinguishes continuous webs/local roots from retained crown growth. Local generated material observations are not strength or physical printing qualification. Frozen annulus/U regressions live in `fixtures/manufacturing/web-roof`; the complete deterministic construction and remaining varying-section limits belong to the [contract](../protocol/manufacturing.md#web-and-roof-infill).

Source-edit campaigns use the [Rust-only generation loop](../../tools/infill-lab/README.md#source-edit-experiments). Candidate deposition must come from the actual Rust engine with fresh independent replay and saved return; Python coordination and evaluator math cannot replace or mutate roads. Verifier/contract extensions precede a new frozen cohort, never a scored edit.
