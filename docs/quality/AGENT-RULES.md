# Quality documentation rules

- Distinguish executed results, proposed targets, and unverified acceptance explicitly.
- Plans and evidence may record milestone progress; canonical agent rules/vision may not become task histories.
- Record environment, fixture/build identity, procedures, failures, measurements and gate decision. Never substitute software rendering or CI compilation for physical GPU acceptance.
- Source availability and licensing procedures must describe the actual packaged artifacts. No public release from an uncommitted dirty worktree without accompanying matching source.
