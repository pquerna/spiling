# Software-only manufacturing protocol and schema

`spiling-contracts::manufacturing` is executable schema authority; generated TypeScript is the authoring data language. The Rust manufacturing crate owns planar compilation, a narrow emitter and independent replay. Core owns transactions/storage. The engine composes them, and the shared client/CLI consume their results. These are software-validation artifacts, **not machine-ready programs, physical printer support or printability certification**.

Native control uses typed gRPC services; project format is 3 and manufacturing data schema is 4. No old-format decoder, migration shim or implicit profile/recipe default exists. SPLT/SPLM/SPLS remain schema 1; [SPLR actual replay display](replay.md) stays schema 3.

## Authoring and trust boundary

An operator may author a TypeScript data module against generated Rust-defined types. Build tooling may execute that explicitly trusted local authoring module to produce JSON; executing authoring code has the operator's permissions and is not a sandbox. The engine never executes TypeScript: it receives bounded inert JSON, rejects unknown/duplicate fields and trailing JSON, and validates it in Rust. A schema capability declaration does not enable unsupported behavior. Ordinary printer data does not require a new backend; genuinely custom behavior requires separately reviewed Rust implementation.

All names, IDs and revision labels below are nonempty strings of at most 256 UTF-8 bytes, without control characters. Numeric process parameters must be finite and positive. Unknown enum discriminants fail decoding. Profile/intent JSON is at most 32,768 bytes. All fields below are required, including explicit `null` manifest option values.

## Printer and recipe data

`PrinterSpecification` fields:

- `schema_version: 4`, `id`, `revision`, `name`.
- `coordinate_frame: "right_handed_millimetres"`: fixed Cartesian XYZ, right-handed millimetres. Layer planning uses the bed plane at `build_envelope.min[2]`, not an assumed global Z=0.
- `build_envelope: AabbMm {min:[f64;3],max:[f64;3]}`: finite ordered strictly positive dimensions.
- `components: MachineComponent[]`, at most 64, unique component IDs.
- `capabilities: PrinterCapabilities {motion_space:"cartesian_xyz",extruders:1,output_dialect,generated_supports}`. Generated breakaway supports require the explicit software capability. Diagnostic bodies require `cartesian_absolute_gcode_v1`; complete jobs require `marlin2_single_extruder_gcode_v1`. Capability declarations do not establish hardware qualification.
- `nozzle_diameter_mm`, `max_feed_mm_s`, `max_volumetric_flow_mm3_s`.
- Required `workflow` is `{kind:"diagnostic_body_only"}` or `{kind:"complete_marlin",job:SingleExtruderJob}`; workflow/dialect mismatches fail.

`SingleExtruderJob` requires bounded `machine_id`, explicitly named Marlin 2 `firmware_version`, `configuration_hash`, `calibration_record_hash`, `homing_contract:"marlin_native_cartesian"`, `home_position_mm`, `nozzle_temperature_c`, `bed_temperature_c`, `minimum_extrusion_temperature_c`, `maximum_nozzle_temperature_c`, `maximum_bed_temperature_c`, `prime_start_mm`, `prime_end_mm`, `prime_filament_length_mm`, `prime_speed_mm_s` and `park_position_mm`. Hashes identify external declarations, not host approval or physical qualification. Temperatures are positive integral Celsius; requested nozzle temperature is within declared minimum/maximum, bed within maximum, maxima are bounded to 500/200°C and priming to 100 mm filament. All lifecycle endpoints and feeds obey the printer envelope/limits; priming also obeys nominal volumetric flow.

The complete-job firmware contract requires native Cartesian coordinates without workspace/home offsets, skew, leveling or restoration, one active extruder, M149/TEMPERATURE_UNITS_SUPPORT, M200 and M420, and no firmware extrusion modifiers or fixed G0 feed override. Configuration/calibration hashes do not prove these assumptions. Prime segments must avoid conservatively expanded all-layer object XY bounds, regardless of Z, holes or gaps; admission includes coordinate-rounding padding. Final park Z must have representable clearance above every object and prime point.

`MachineComponent` has `id`, `role: "bed"|"toolhead"|"fixture"`, a checked `pose: RigidPoseMm {translation_mm:[f64;3],rotation_xyzw:[f64;4]}`, and `shape`:

- `{kind:"box",bounds_mm:AabbMm}` with positive dimensions in component-local millimetres.
- `{kind:"cylinder",radius_mm:f64,height_mm:f64}` with positive dimensions; cylinder is local +Z with base at local origin.

Pose is proper finite rigid motion with a unit quaternion: no scale, shear or reflection. Fixed component conservative bounds additionally exclude finished surface occurrences; this is not a rendered/executable machine model or a swept-tool collision certificate.

`PlanarPrintRecipe` requires `id`, `revision`, `material_id`, `material_revision`, `filament_diameter_mm`, `layer_height_mm`, `bead_width_mm`, `perimeter_count`, `infill_fraction`, positive physical `top_skin_thickness_mm`, `bottom_skin_thickness_mm`, `print_speed_mm_s`, `travel_speed_mm_s`, `flow_multiplier`. Perimeters are 1..8; layer height is at most bead width; finite density is in `(0,1]`, with 1 meaning solid interior and smaller values sparse rectilinear interior. Skin thickness uses conservative whole-layer horizons. Print/travel speed must not exceed printer feed limits. Nominal bead area is `(width-height)*height + pi*(height/2)^2`; flow is area × multiplier × print speed and must not exceed the explicit volumetric limit. Filament area is `pi*(diameter/2)^2`. Numeric overflow/underflow that destroys finite positive areas is rejected. These are declared geometric accounting models, not material calibration, strength or measured deposition physics.

Required `process:ProcessPolicy` declares first-layer speed/flow factors, first-layer and later fan PWM, bridge speed/flow/fan, sole authoritative positive `max_bridge_span_mm`, and tagged retraction disabled or enabled with positive distance/speed/minimum travel and nonnegative Z hop. Speed factors are in `(0,1]`; actual per-layer height, flow and feed remain bounded by the printer. `supports:SupportPolicy` is explicitly disabled or breakaway with density `(0,1]`, positive XY clearance/interface thickness and nonnegative Z gap. No default policy or duplicate support bridge-span authority exists. Fan PWM is commanded process state, never a cooling measurement.

`ManufacturingIntent {printer:PrinterSpecification,recipe:PlanarPrintRecipe}` validates both declarations and their cross-constraints. `decode_intent(bytes)` bounds input before decoding; direct DTO consumers must call `validate()`.

## Normalized plan

`NormalizedPrintPlan` has `schema_version:4`, `layers`, positive finite `sampling_tolerance_mm`, `offset_tolerance_mm`, `surface_tolerance_mm`, `layer_quantization_mm`. Native sampling remains 0.005 mm and offsets 0.005 mm; the separately declared rib-profile chord approximation bound is 0.001 mm. Planner/emitter/verifier producer versions are 4; SPLR role/layout semantics do not change.

A `PrintLayer` has consecutive schedule `index`, increasing deposition `z_mm`, required true `height_mm` from the previous layer or bed, interior `section_z_mm`, `region_coverage` and deposition paths. Nominal grid, admitted horizontal events and exact top determine scheduling; partial final layers use actual height for bead/flow. Native analysis rejects unresolved small/topological/resource conditions. Internal empty support-contact-gap layers are admitted only for enabled breakaway supports, exactly zero object/support areas and nominal volumes, bounded contiguous height by declared Z gap, and adjacent printed support-interface then actual object deposition. No leading/trailing empty layer or fictitious bead fills a contact gap. Independent replay proves the schedule binding; packed replay honestly skips empty layers.

A `DepositionPath` has `kind:"perimeter"|"solid_fill"|"bottom_skin"|"top_skin"|"sparse_fill"|"bridge"|"support"|"support_interface"` and at least two finite envelope-contained points at exact layer Z. Segments have positive XY length; perimeter closure is explicit. Layer-specific bead/flow derives from true height and explicit process policy. Plans are capped at 4096 schedule layers and 100000 total object-plus-support deposition segments. Nested JSON admission shares one cumulative segment budget before point-vector growth; empty or single-point paths cannot bypass it.

Native BREP sections and rigid occurrences remain geometry authority. Same-material object sections preserve holes/islands, inward walls and disjoint skin/interior ownership. Physical-distance skin horizons classify floors and roofs. Unsupported spans become bounded bridges or clearance-clipped breakaway support/interface according to explicit policy; support never mutates source BREP or object material ownership. Sloped native planar/cylindrical sections require numerical admission gates. No mesh repair, silently removed feature or triangle fallback exists; numerical residuals are not physical accuracy certification.

`PlanarRegionCoverage.section_area_mm2` is realized object material D, with required separate `source_section_area_mm2` (original native M) and `surface_added_area_mm2` (D minus M). Additive-only construction checks `section = source + added`; untextured source has `source=section,added=0`, and support-only/contact-gap layers have both zero. Wall/skin/interior/void/hole ownership partitions D, with separate object-only `nominal_deposition_volume_mm3`, `support_area_mm2` and `support_nominal_deposition_volume_mm3`. Protected native holes remain excluded. Sparse nominal void is interior area × `(1-density)`. Geometric added volume is added area × true layer height, not measured extrusion, grip or physical coverage. Nominal deposited volume and independent replay use actual path lengths, bead area, true heights and process flow factors.

Native footprint reuse is confined to admitted XY-invariant open slabs. Sloped or tilted carriers use actual native scheduled sections and explicit numerical gates rather than accumulating an undeclared display approximation. Horizontal events, offsets and sampling retain separate bounded tolerances; failure is explicit.

## Source-backed whole-face finish construction

Captured `surface_overlays` is the single ordered whole-face finish channel, not a profile flag or recipe material change. Enabled definition layers resolve in stored order, then enabled occurrence layers; the last matching layer wins. Smooth explicitly overrides lower ribs; disabling/removing it reveals the lower finish. Disabled and shadowed layers remain captured provenance/fingerprint content, and every saved target must name an actual face in the exact rebuilt native table.

VerticalRibs requires the immutable native certificate for one four-line, unholed, full-height rectangular exterior vertical planar face with an outward global supporting material side. The initial manufacturing lane additionally requires an upright bed-anchored invariant extrusion: local Z maps to either sign of build Z, without tilt, intermediate shelves or sloped/tilted carriers. Source-local horizontal millimetres and phase follow the occurrence pose. Cylinder, sloped, partial-height, recessed, ambiguous co-carrier and unsafe/unsupported combinations refuse explicitly, never succeed without the requested finish.

The outward field is a smooth raised-cosine periodic profile multiplied by a smooth end taper, constant through the full source height. Protected end bands have nominally zero displacement, original end vertices remain exact, and newly constructed guard/sample coordinates reserve an explicit arithmetic bound; additions close at bed/top with no height expansion. Require pitch ≥ four bead widths, protected margin ≥ two bead widths, depth ≥ four finish approximation bounds and depth ≤ half a bead width; the face must fit both margins and a full pitch. Conservative second-derivative sampling bounds chord error to 0.00099 mm, with 0.00001 mm reserved for native-frame agreement and bounded outward-directed rounding, totaling at most 0.001 mm independently of native/offset tolerances. Compile also requires a resolvable rib peak surviving ordinary first-wall erosion; lost or unresolvable depth refuses.
Sampling includes both half-pitch taper breakpoints. Each ramp uses the conservative product second-derivative bound; the constant-amplitude interior uses `depth * (2π/pitch)^2 / 2`. Each interval count independently satisfies the same 0.00099 mm chord bound. Native chain parameter insertion only subdivides those intervals; it does not flatten the waveform or enlarge the budget.

Each addition A extends inward by one quarter bead width; strictly interior overlap witnesses plus native-boundary intersection/exclusion checks prove the positive collar belongs to original M and contains no protected hole. The native certificate must match one unique full-span contiguous monotone exterior sample chain by both trimmed endpoints, global supporting material side and material-left winding, including closed-ring wrapping. All requested faces are proved against original M; profile sampling merges every original chain parameter and anchors each interval to its actual native segment. Bounded outward samples replace only the active face intervals. Every original material point remains included in D; untouched/protected vertices, full-span endpoints and hole rings retain their exact coordinates. Active-face native samples may become interior M instead of explicit D boundary vertices. Exact robust orientation, local/global progression, original-point inclusion and nonintersection establish mathematical `D = M union A`, with positive added area and unchanged island/hole ownership, without a floating Boolean re-quantizing unrelated geometry. Directed rounding applies only to new samples and refuses beyond the construction bound; missing-material slivers are not accepted with epsilon tolerances.

Source M remains separate for area/provenance accounting. In overlapping source Z interiors, finished occurrences must have disjoint closed XY bounds; their exact rings are appended without another source/derived union overlay. Untextured occurrences retain the existing native union path. The same D enters invariant-span identity, ordinary wall/fill/skin ownership, actual deposited-stroke bridge/support checks, regenerated hatch alternatives and clearance corridors. No jitter of prebuilt perimeters, emitted-byte mutation, mesh matching, source-only regeneration or new path role is used.

Preflight admits exact native face metadata and process bounds, expands conservative placed extents, and excludes another occurrence, fixed component bounds and complete-job priming; actual section/overlap/topology/offset/anchor proof remains a Compile obligation. Conservative expanded-AABB exclusions may reject geometrically separated configurations whose boxes overlap or touch in XY within overlapping Z interiors. Sampling, staging, retained geometry, cumulative Boolean/boundary-proof work and final object/support segments retain existing bounded admission/cancellation. Exported construction is not an edited BREP, physical texture/grip certification or printer qualification.


## Provenance, reports and immutable bundles

`ManufacturingProvenance` contains `project_id`, captured `input_revision`, `input_hash`, `definitions:StoredDefinition[]`, `occurrences:OccurrenceRecord[]`, explicit `intent`, full ordered `surface_overlays`, `kernel:{name,version,revision}`, and explicit `planner_version`, `emitter_version`, `verifier_version`. Captured persisted source labels/units/uncertainty remain authoritative; native reimport labels must not replace them. Definitions/occurrences obey shared identity/reference/pose/provenance caps and every definition is referenced.

`input_fingerprint(project_id,definitions,occurrences,intent,surface_overlays)` validates these inputs, sorts definitions by definition ID and occurrences by occurrence ID, then SHA-256 hashes the UTF-8 compact JSON emitted by Rust serde_json in this field order:

```text
{schema_version:4,project_id,units:"mm",frame:"right_handed",definitions,occurrences,intent,surface_overlays}
```

Every record/intent field uses its Rust declaration order and serde spelling, without whitespace. Source bytes enter through source SHA-256 and definition identity; source units, retained labels and declared uncertainty are included. Revision/allocator/history/artifacts/timing are excluded. Algorithm/kernel provenance is additional bundle content identity. This is a Rust-defined canonical serialization algorithm, not a promise that arbitrary JavaScript JSON number formatting is interchangeable. Get/status does not rehash geometry on its hot path.

`VerificationReport` preserves bounded verified/coverage/limitations and position/extrusion errors, object-only deposition segments/volume/filament and actual travel count. Separate required support segment/volume/filament fields exclude support from object totals; lifecycle/prime totals remain separate. `retraction_count` and `retracted_filament_mm` account withdrawn feeder distance; paired recovery never counts as deposition or prime. Measurements are finite nonnegative, labels bounded, and stored verified:true never substitutes for fresh independent actual-program replay.

`ManufacturingSummary` contains schedule layers, paths, object-only deposition/volume/filament, separate support deposition/volume/filament and software_only:true. Whole-event/deposition budgets include supports, but reported object material ownership never does.

`ManufacturingBundle` contains exactly `schema_version:4`, provenance, plan, actual program and verification. Immutable asset hash covers exact compact UTF-8 JSON without self-reference. Artifact record hashes, byte count and summary remain bounded checked manifest metadata. Serialized and allocated bundle limits stay 16 MiB; Core's 64 MiB active/staging/history capacity accounting and durable source/storage authority are unchanged.

Public schema APIs are printer/recipe/component/capability/intent `validate()`, plan `validate(&intent)`, provenance/report/summary/artifact/bundle `validate()`, `decode_bundle(bytes)`, bundle `summary()` and `validate_record(&record)`. Summary/record matching require an already validated bundle. Record matching checks semantic input hash and summary; caller separately checks exact actual-byte hash and byte count. Schema validation does not parse/replay the program or confer replay success.

## Emitted program and independent replay

Programs remain conspicuously SOFTWARE VALIDATION ONLY, NOT MACHINE READY. Explicit modal/lifecycle commands establish the declared software coordinate/thermal/extrusion contract. XYZ travels/deposition carry explicit F, stationary retract/recover use real E-only G1 commands, and actual first-layer/bridge feed/flow/fan policies are realized. Fan S0..255 commands bind the next queued motion, not current physical cooling. Complete configuration declares ordinary default cooling fan, no laser synchronization and external E-only retraction; no firmware truth is inferred from a hash. Six-digit XYZ/feed and eight-digit E quantization must retain representable movement/extrusion. Complete jobs include independently checked prime, barriers, clearance lift/park and shutdown. No submission/connector or arbitrary macros exist.

An independent verifier decodes command state from emitted bytes, not emitter helpers or a copied move buffer. It checks exact workflow modes/lifecycle/order, malformed/duplicate/nonfinite fields, thermal targets/waits, envelope, speed, nominal flow, object-excluded priming, positive deposition versus travel, expected path ordering/counts, positions and extrusion. Missing/extra/tampered commands fail verification. Coverage includes complete-job command semantics, not physical startup/homing or sensor truth. Replay explicitly excludes physics, collisions, component swept volumes, actual firmware/configuration behavior, calibration and physical printer support. A successful replay proves only the declared software semantics.

`inspect_bundle(&bundle,&bundle_hash,output,&cancel)` produces `ManufacturingInspection {report,provenance,replay}`. `VerificationOutput` is explicitly `report_only` or `report_and_motion`; `verify_bundle` retains its report-only API. The same independent command decoder streams validated actual XYZ, absolute E and F into an optional bounded SPLR byte sink. Layer/kind attribution comes from the validated expected-point iterator, never emitter comments. Report-only work allocates no display buffer, index or display/program hash. Failed decoding or cancellation drops the unpublished optional sink; no partial display result exists.

`ManufacturingInspectionProvenance` captures `project_id,input_revision,input_hash,surface_overlays,kernel,planner_version,emitter_version,verifier_version` from the actual bundle, with the same bounded labels. It is not reconstructed from the current project. `ReplayDisplayDescriptor {info,resource}` binds display metadata to the original bundle hash and input hash; its resource is a separate immutable artifact with MIME `application/x-spiling-replay-motion`, exact SPLR length and actual-byte hash. Native and client validators check correspondence to the bundle record; the packed validator checks every record and aggregate without allocating a motion-object vector.

## Native services and immutable retrieval

The typed `spiling.engine.Manufacturing` service owns Get/SetIntent Execute and standard Google-operation Preflight/Compile/Verify. Every long request captures explicit project base revision, session and optional canonical request UUID. Preflight is nonmutating, uses the same bounded native worker/revision/cancellation ownership and returns no manufacturing artifact.

The Rust/TypeScript shell adapter uses `ManufacturingCommand` for `get`, `set_intent`, `compile` and `inspect`; `inspect` maps to Verify with captured project revision and required explicit `output`. Protobuf output unspecified or unknown is rejected, not implicitly report-only. Status contains project info, optional intent, optional artifact record and an optional immutable bundle resource descriptor. The adapter reports accepted work as `operation_accepted {operation:NativeOperationView}`, with a Google operation name, never a public numeric job handle.

`PreflightReport {input_revision,eligible,software_only,checks}` has at most 256 checks. Each check contains bounded code/message, severity error/warning/info and optional occurrence/face IDs. Eligible means inexpensive input/profile/orientation/placement admission only, not native slicing or physical printability. Explicit informational checks state that native layer/support/bridge/offset analysis occurs during Compile and physical qualification is absent. Native result `ManufacturingPreflight {report}` must match captured revision and have no immutable outputs.

Native metadata and result use the protobuf `NativeOperationMetadata` and `NativeOperationResult` Any types. Compiled results contain project info, record and resource; verified results contain record, fresh report, bundle resource, captured inspection provenance and optional replay display descriptor. All bundle and replay resources must be present in immutable outputs; conversions reject missing provenance, unsupported frames, malformed counts/hashes/MIME/size or record bindings. Standard Operations Get/Wait/Cancel and Engine WatchOperation provide observation and explicit cancellation. Dropping or timing out a unary RPC does not cancel accepted work. Unfinished retained operations become interrupted/aborted on engine restart; old session results are historical, not active native handles.

Compilation captures immutable project inputs and their persistent revision. Core remains sole writer. After compile/replay, ACK publication checks project/session/revision/cancellation again before the normal artifact transaction. Intent/geometry changes invalidate artifact in the same transaction; undo restores coherent inputs+artifact. Publication advances persistent revision, but provenance keeps the original compiler input revision. Read-only allows inspect/replay, never intent edit/compile publication. Durable operation output and success are published only after native promotion ACK/core commit.

Artifacts.GetArtifact and standard Google ByteStream.Read retrieve immutable bundle bytes by the returned resource descriptor. Descriptor size/hash must match the manufacturing record; bound the total before allocation and validate streamed size, exact actual-byte SHA-256, strict UTF-8/schema, captured semantic input hash and summary. Bundle size remains at most 16 MiB. There is no ReadChunk command, correlation frame header or kind-4 payload. ByteStream flow control is separate from job observation/cancellation.

Report+motion reserves 32 MiB for single-job ledger publication (report-only 16 MiB). Fresh report/provenance/display descriptor and packed bytes are published together in the terminal SQLite transaction only after native promotion ACK. Pre-ACK cancellation drops staging; a winning successful ACK/terminal commit is not rolled back by late cancellation. Replay is derived transient/runtime-ledger state, not a new Core manifest asset or saved verified authority. ByteStream replay reads are bounded to at most 1 MiB per stream chunk; clients bound and validate the complete immutable bytes before display or export. The renderer never replans or reparses the machine program.

Canonical gRPC/Google Status carries typed domain error details. Domain errors remain recoverable; transport/contract failures do not fabricate success or retry uncertain mutations. Saved bundle JSON and the printer-authoring JSON are domain/storage formats, deliberately distinct from protobuf RPC messages.

Manufacturing errors are `invalid_specification`, `unsupported_capability`, `unsupported_geometry`, `no_intent`, `empty_project`, `stale_revision`, `verification_failed`, `resource_limit`, `cancelled`, `io`, `corrupt_artifact`, `read_only`, `busy`. Messages are bounded to 2,048 UTF-8 bytes. Invalid specifications are not replaced by defaults or fake fallbacks.
