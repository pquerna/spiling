# Engine geometry ownership rules

- Compose Core transactions and the public geometry/manufacturing facades; never depend directly on SolidCore or maintain competing authoritative project state. Native command/result slots have capacity one. Native objects stay on the sole worker; private execution correlations are not another public job service.
- Display progress uses one coalescing, job-tagged slot into existing Operations stage metadata. Report actual candidate/audit phases and completed faces per attempt; work divided by an allowance is not progress. Ignore updates after cancellation, promotion or terminal status. One borrowed display guard covers every rebuilt definition of an open operation, including retries.
- Stage import/open and reserve live pins before Decide/promote. Commit prepared Core state only after worker ACK. Retain the complete old project, storage and history/native pins until replacement succeeds; cancellation or stale/failing work preserves them. Reclaim against the latest replaceable pin snapshot at safe boundaries.
- Core retained sources drive definition/display pins, including undo/redo; only its current snapshot drives scene pages and live face references. Definition pins and consumer leases are independent. Manufacturing publication/history must not invalidate unchanged geometry caches.
- Analyze case edits use current native source-face tables and persistent project revisions; every open rechecks retained patches, including source reuse. Authoring is not a numerical receipt. The assumed-law macro consumer captures immutable cases/recipes on the dispatcher and admits complete native material/span ownership on the sole worker, retaining one original operator there. Load-only reuse excludes no construction/pose/restraint/law dependency. Revision/cancel/ACK gates own field publication; durable operation artifacts do not imply portable project result attachment. Case-only edits preserve scene and manufacturing inputs; Core owns source binding, history and persistence. [Analyze contracts](../../../../docs/protocol/analysis.md) own coverage and evidence limits.
- Bed preparation distinguishes native-bounded support from explicitly sampled tolerant-model placement; model extrema never become native contact evidence. Manufacturing admission keeps its own source/recipe-bound obligations. Check definition, pose and query bindings; Core alone applies the prepared pose. Raw source/display bounds and material bounds are distinct authorities; neither establishes closed-material compilation eligibility.
- StartSection validates and captures the raw plane. Worker query input and SPLS metadata derive independently from that same request: repeated normalization of a normalized f64 vector need not retain exact coefficients. Preserve the public normalized-request identity and independent native residual checks.
- Section source preparation uses `MAX_PREPARED_SECTION_SOURCE_BYTES`, including retained proofs. Prepared sources, live query results and builder capacities coexist within `MAX_PREPARED_SECTION_BYTES`, independently of the 16 MiB packed-output cap. One `GeometryWorkBudget::query()` covers the complete request. Subtract retained capacities before queries/growth; release a source after its last occurrence. Geometry owns pose pullback, metric errors and canonical world loops; meshes never supply section authority.
- Source/proof growth uses engine-observed machine/container/address-space headroom and optional `SPILING_SOURCE_MEMORY_BYTES` total. Count actual unique source Vec capacities across current/history/prepared ownership, plus retained native proofs; existing residency already reduces observed headroom. Reserve incoming allocations before native growth. Saved return freshly verifies stored bytes while sharing unchanged source/native/display allocations. Required BREP and tessellation are legitimate residency: share them rather than duplicating or rebuilding them. This admission is not whole-kernel RSS accounting; other geometry/display envelopes remain separate.
- Image work captures remaining 4 MiB canonical headroom, including prepared candidates, before normalization. Duplicate content still requires incoming allocation headroom. Core rechecks it at promotion. Finish edits preserve scene/display state; every open validates stored targets against the actual rebuilt/reused face table.

Parent engine rules own RPC, watchdog, save and durable-publication semantics. [Manufacturing ownership](manufacturing/AGENT-RULES.md), [wire authority](../../../../docs/protocol/control.md) and real-child geometry/project/manufacturing checks govern integration; source-wiring assertions do not.
