# Desktop engine supervision vision

Translate real native child ownership into one recoverable gRPC authoring/diagnostic workbench. Dead engines never report running; typed domain errors preserve healthy sessions; explicit stop differs from interruption. Shared EngineClient owns supervision, EngineRpc owns RPC access, core owns project/storage, and the engine's single durable scheduler owns native and diagnostic work.

One lazy child begins with an unattached project and a persistent diagnostic operation store. Shell-private bounded tokens admit source/project/export paths; the only remembered project state is the attached saved checkpoint route. Standard Operations names observe/cancel native work without blocking cleanup; raw ByteStream bytes use checked domain metadata and display limits. Fresh manufacturing inspection authority is transient, request/session/content bound and cleared on reopen/lifecycle changes; export uses the common exclusive transaction. Retained historical outputs never establish live scene, manufacturing or checkpoint ownership for a different session.
The operator bridge admits full inert intent through bounded native dialog tokens, preserves profile declarations and exposes separate software input Preflight. Bed preparation delegates certified-bound calculations to the shared Rust client and leaves revisions/history/read-only to Core. True schedule thickness and empty support-contact gaps are native checked metadata, not renderer estimates or fabricated motion.

The shell does not retain native objects, implement project transactions/storage, replay edits, accumulate unbounded transfer bytes, plan manufacturing or add a second handshake model. Restart explicitly reopens only saved storage. Startup-gated fixtures use production path tokens without unrestricted renderer filesystem access.

Acceptance requires actual process interoperability, durable diagnostic behavior, fatal/recoverable errors, native dialog/token operations, independent cancellation and no surviving child after stop/close during native work or transfer. Visible picking/rendering and distributable certification remain separate reference-hardware gates.
