# Native desktop shell rules

- Own CEF composition, native invoke ACLs, sidecar supervision and distributable configuration only. Geometry, protocol transport and WebGPU rendering belong to the engine/client/frontend owners.
- Pin Tauri `3.0.0-alpha.4`, tauri-build `3.0.0-alpha.3`, and tauri-runtime-cef `3.0.0-alpha.5` exactly. The runtime pins CEF `152.3.0`. Depend directly on runtime-cef so upstream build/CLI detection packages CEF. Keep the upstream `cef_entry_point` attribute; do not implement helper-process unsafe code or a Wry fallback.
- Application invokes are explicitly listed in build.rs and the local-only `main` capability; the only core permission is closing the main window through the same deferred-cleanup path as a native close request. Add no remote capability or shell/process/fs permission. The frontend probes WebGPU before invoking engine_start; starting the desktop alone must not spawn an engine.
- CEF defaults remain intact: debugging is disabled unless `SPILING_CEF_DEBUG_PORT=1024..65535`; only exact `SPILING_CEF_UNSANDBOXED=1` disables the sandbox and only exact `SPILING_CEF_SOFTWARE_GPU=1` selects diagnostic SwiftShader. Neither is a production support claim. Upstream Auto sandbox warns and runs unsandboxed on Windows, and can do so for constrained Linux AppImages; do not conceal that limitation.
- Resolve installed `spiling-engine[.exe]` adjacent to the actual desktop executable; CEF Debian packages relocate the desktop into `share/Spiling`, so resolve their external binary in `bin` under the same installation prefix. Never search PATH, the current working directory or arbitrary ancestor locations. Debug builds alone allow an absolute `SPILING_ENGINE_PATH`. Engine/shell are one build; no version override is supported.
- Close and exit requests defer exit while asynchronous client cleanup completes, reject new engine operations, and retain the client mutex until shutdown finishes. See [engine rules](src/engine/AGENT-RULES.md).
- Root tools generate contracts/notices and build/copy the target-suffixed external binary before invoking the pinned `@tauri-apps/cli` `3.0.0-alpha.4`. Root `pnpm dev` launches the frontend through the Tauri before-dev hook; `pnpm package` builds it through the before-build hook. A bare Cargo executable is not a macOS CEF application bundle.
- Root tools set `CEF_PATH` to the ignored repository `.cache/cef` unless an explicit matching distribution is supplied. First CEF compilation downloads approximately 1 GB; the same cache feeds packaging. Linux requires GTK4 development files, native build tools/pkg-config and CEF/Chromium runtime libraries; headless evidence requires an X display. Windows requires MSVC tools; macOS requires Xcode command-line tools and upstream framework/helper signing.
- Ship LICENSE.md, NOTICE.md, license/source documentation and root-generated `.cache/release/` provenance/third-party notices. Original icon binaries have adjacent OSL sidecars and editable SVG provenance; PNG is required by Unix codegen, ICO by Windows resources and ICNS by macOS bundles. Tool-generated Cargo.lock and gen/schemas retain upstream tool output without hand-added headers.
- Validate through real desktop invokes: start/status, 64-byte raw triangle, operation progress/cancellation, intentional stop, unexpected exit, interrupt/restart and close without orphan processes. Inspect distributable CEF/sidecar/license/notice contents on each claimed platform. Software-GPU/headless smoke is not hardware or cross-platform acceptance.
