# Native diagnostics, authoring and inspection consumer rules

- Use the shared EngineClient/EngineRpc exclusively: authenticated typed gRPC services, Google Operations names and Artifacts/ByteStream. No framed transport, JSON command tunnel, second scheduler, geometry/kernel dependency or alternate planner.
- Diagnose observes real readiness; triangle remains an explicit synthetic diagnostic. Job watches the existing durable diagnostic operation and fetches incremental immutable outputs. Optional --store retains operations across fresh runs; --request-id is the caller's AIP-155 UUID, never an automatic retry with a new identity.
- Geometry accepts a schema-version-1 evaluation recipe or repeated native --source paths, optional native --section and exclusive --out directory. Validate keys, references, poses and numeric inputs before spawning; import parts sequentially, then add instances. Recipes are evaluation inputs, not saved projects.
- Project create/edit/save/open/inspect/recover commands orchestrate typed project, geometry and manufacturing services. Ordered flags perform imports/shared placements/removal/undo/redo/checkpoints and --intent JSON_FILE/--place-on-bed ID/--center-on-bed ID/--preflight/--compile/--verify/--manufacturing-out NEWDIR. Observe authoritative project and manufacturing status after every operation. Intent files are bounded inert full JSON declarations, never executed TypeScript or default machine permissions; Rust service validation owns acceptance. Inspect/read-only permits preflight/replay/export but rejects intent/pose mutation, compile publication and saves locally.
- Ordered `--surface-finish OCCURRENCE FACE_ID SCOPE FINISH_JSON`, `--surface-image OCCURRENCE FACE_ID SCOPE IMAGE_PATH PARAMETERS_JSON`, remove and enable flags use existing typed Projects operations. Scope is definition|occurrence; resolve live native FaceRef and persistent revision immediately before assignment. Reject authoring pre-spawn in read-only mode. Preserve schema3 authoritative overlay/image receipts; image decoding, carrier certification, field realization and resource admission remain engine-owned.
- Ordered `--process-set OCC SCOPE FRACTION`, `--process-set-box OCC SCOPE MIN_X MIN_Y MIN_Z MAX_X MAX_Y MAX_Z FRACTION PERMISSION` and `--process-reset OCC SCOPE` use Projects EditProcess with checked source identity/revision. Bounds are finite, ordered definition-local mm (min inclusive/max exclusive). Required permission is `none`, `separator-wall` or `horizontal-diaphragm:MM` with finite positive physical thickness centered on the source-Z boundary. Neither consent nor schedule advice proves material/support/strength. Whole Set updates only WholeOwnedVolume; Box Set updates the exact-scope intended box, preserving IDs; Reset clears every exact-scope layer. Bounded `--process-edit EDIT_JSON` uses Rust-owned edits/allocation. Read-only resolve reports whole-owned base/provenance excluding boxes; the authored document retains spatial intent. No client precedence resolver or recipe rewrite.
- Filesystem operations preserve native OsString bytes/code units; only bounded JSON display labels are lossy UTF-8. The default engine is beside the CLI. Commands start private fresh child processes, including reopen; retained operation storage does not restore native session handles.
- Always fetch each available unique mesh/section chunk through its returned immutable resource descriptor and ByteStream, even without --out. Validate hash, size, packed layout, session/artifact/revision identity and complete ordered manifests through borrowed contract views. Unavailable definition display retains typed refusal, authoritative native bounds and the complete source-face table; never request/release a missing artifact or invent mesh counts. Nonempty scenes may have zero mesh bytes. Keep one payload live; enforce pagination/count/identity budgets. Report native f64 per-occurrence areas and placements, never geometry manufactured from display triangles.
- Native operation observation polls standard Operations by name every 100 ms without a second watchdog. Match operation name/session and classify typed geometry/project/manufacturing errors. On recoverable manufacturing errors reconcile authoritative project/intent/artifact status before cleanup.
- On recoverable save failure query authoritative project status without retry. Preserve dirty/save_uncertain evidence: a committed-but-unsynced checkpoint is not a confirmed save or assumed rollback. No success stdout or completion manifest on save error.
- --out and --manufacturing-out admit previously nonexistent directories before spawn, use exclusive files and roll back only their own handles/inodes on failure, without recursive deletion or following substituted symlinks. Never overwrite/delete foreign replacements. Completion manifests and final stdout follow successful observed child reap; output failure still rolls back owned files.
- Manufacturing export independently replays through the engine and retrieves the descriptor-bound, size/hash/input/schema/summary-validated bundle through EngineClient. Export plan.json/program.gcode/verification.json/provenance.json; verification.json is the exact fresh replay report, not the persisted flag. Identify exported content even if later ordered edits invalidate the active artifact. Every manufacturing report states software_only and not_machine_ready; no physical readiness or printability claims.
- Bed preparation uses revision-captured native support queries for the actual stored pose, not rotated AABB minima or a client-side signed-permutation solver. Preserve quaternion and apply only the returned translation through authoritative SetInstancePose, with normal invalidation/undo/revision semantics. Center moves XY and places Z on the declared bed; place changes Z only and rejects an out-of-envelope result.
- Explicit --preflight preserves the whole report: disposition (admitted/refused/unresolved), every check's evidence/required, actionable diagnostics, occurrence/face identities and captured input revision. It is nonmutating: refused and unresolved remain inspectable operator reports, not failed compilation. Optional Compile-only native checks may be pending, indeterminate, unsupported or failed without refusing otherwise admitted metadata; admission never authorizes Compile. Native summary certification covers actual occurrence queries/slabs and scheduled material under source_feature_coverage, not automatic global composed union-boundary/feature proof. Preserve requested/achieved bounds and all coverage scopes in JSON; software_only never establishes physical qualification.
- `project create/inspect --replay-out NEW_FILE` requests a fresh ReportAndMotion inspection and uses `EngineClient::fetch_replay_display` before writing SPLR actual-program bytes. Include its descriptor and captured provenance in the JSON report. The new file is admitted exclusively before spawn and owned-handle rollback removes only that file on any failure; commit follows successful observed child reap/stdout. All other inspection callers explicitly select ReportOnly. Filesystem safety is shared directly from `spiling_engine_client::export`, not duplicated in CLI.
- Ordered `--surface-image-out HASH NEW_FILE` is read-only-safe and retrieves fresh GetSurfaceImage through the checked bounded ByteStream client. Bind project/revision/hash and export canonical PGM using the same exclusive OutputFile lifecycle; no direct project asset access or original PNG dependency.
- Ordered appearance/optical flags author engine-owned studies without geometry. `--appearance-compare`/`--optical-compare` retrieve checked engine reports, never evaluate locally. Explicit acceptance requires the latest complete current-revision comparison; optical selection is requested, best retained, or original grid index. Compare/stored report export permit read-only; authoring/acceptance rejects it before spawn. `--optical-study` decodes bounded typed JSON, not a source-path dependency or calibrated material model. Both report exports share exclusive OutputFile admission, rollback and observed-reap commit. Named reference estimates do not imply mixed printing.
- Create/edit checkpoint final state; open does not implicitly save. Save preserves undo/redo history. Fresh inspection reopens engine-owned source assets after originals are removed.
- Exercise node --import tsx tools/smoke-cli.mjs against built binaries and SPILING_TEST_ENGINE=PATH cargo test --locked -p spiling-cli -- --ignored --test-threads=1. Actual-child regressions cover source deletion/reopen, ordered checkpoints and history, transfer/sections/faces, failure/reap/rollback, fresh manufacturing replay/export and non-UTF8 paths. Parent integration verification runs these sequentially under its resource limits; do not claim unexecuted checks.

Software-only operator workflow:

```sh
spiling-cli project create PROJECT --import fixtures/geometry/box-mm.step --intent fixtures/manufacturing/solid-fill.intent.json --center-on-bed 1 --preflight --compile --verify --manufacturing-out NEW_EXPORT --replay-out NEW_MOTION.splr --engine ENGINE
spiling-cli project inspect PROJECT --preflight --verify --manufacturing-out NEW_REOPEN_EXPORT --replay-out NEW_REOPEN_MOTION.splr --engine ENGINE
```

Two shared occurrences with independent sparse spacing (use new project/export paths):

```sh
spiling-cli --engine ENGINE project create PROCESS_PROJECT --import fixtures/geometry/independent-exporters/occt-tapered-fitting-mm.step --intent fixtures/manufacturing/complete-sparse.intent.json --center-on-bed 1 > created.json
definition=$(jq -r '.occurrences[0].definition_id' created.json)
spiling-cli --engine ENGINE project edit PROCESS_PROJECT --add "$definition" '{"translation_mm":[140,110,0],"rotation_xyzw":[0,0,0,1]}' --process-set 1 definition 0.20 --process-set 2 occurrence 0.60 --process-resolve 1 --process-resolve 2 --preflight --compile --verify --manufacturing-out PROCESS_EXPORT
spiling-cli --engine ENGINE project inspect PROCESS_PROJECT --process-resolve 1 --process-resolve 2 --verify --manufacturing-out FRESH_PROCESS_EXPORT
spiling-cli --engine ENGINE project edit PROCESS_PROJECT --process-reset 2 occurrence --process-resolve 2
```

The final reset inherits `.20` and invalidates the artifact; reset definition scope to inherit the recipe. For the unchanged rounded housing, use `housing-ordinary.intent.json` for uniform Fine0.10 mm with both axes AlternatingXY, then `--process-set 1 definition 0.60 --process-set-box 1 definition -1 -1 -1 25 19 5.03 0.20 horizontal-diaphragm:0.23` for a lighter lower interior and one centered permanent plate. The separate fixed-X `housing-h1-fine/combined` pair owns the axis-constrained XY-separator optimization control; it is not the ordinary default. Source-Z is not world Z. Compile separately admits the full slab, strong native material/bead/hole proof and actual lower/upper/wall attachment. Unsupported thickness may offer schedule-admissible choices requiring Compile, never silent rounding. Explicit JSON edits use returned IDs and tagged permissions; Erase clears only its layer, Reset the complete scope. The engine alone resolves spatial precedence; whole-owned base never claims uniform box density.
