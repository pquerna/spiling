# Engine API authority rules

- Protobuf schemas own the native Engine, Geometry, Projects and Manufacturing gRPC API. Vendored Google Operations, Status and ByteStream schemas retain their Apache license and upstream bytes. No Tauri, renderer or kernel dependencies.
- Build generated native types with pinned vendored protoc and tonic/prost. Checked `native` adapters reapply domain validation in both directions; never use unchecked protobuf-to-domain `From` or JSON command/result tunnels. Domain/persistence serde schemas remain deliberately separate.
- Project/manufacturing readers are strict, without compatibility defaults. Planner identity binds complete original-source realization admission, automatic source-associated walls and material-first skin/residual ownership alongside one actual schedule, source-bound zones, permanent plates and mixed regional/mandatory-skin bridges. Constant/per-edge widths share checked allocation-free edge consumption and immutable Wall ownership survives Bridge. Emitter/verifier identity independently binds actual XYZ6/E8 commands, dimensions and owner associations. ENGINE_BUILD_ID identifies the coordinated semantic generation; executable constants and canonical protocols own current values. Policies/limits remain software declarations, not physical qualification.
- The complete original-source admission above describes current source5/planner23. [ADR005](../../docs/adr/ADR005-native-first-development-geometry.md) adopts a pending native-first DEVELOPMENT replacement, not a second reconstructed solid or transferred qualification. Existing kernel/planner identity and report coverage/limitations own the eventual reliance/limits; no parallel schema or runtime report change precedes coherent activation.
- Rust adapters derive the sole shell view; TypeScript is generated by `cargo run -p spiling-contracts --bin generate`, with `--check` for drift. Never hand-maintain another wire model. Public operation names use Google Operations, not private native task IDs.
- Diagnostic metadata/results and limits remain distinct from native metadata/results and mesh/section/bundle budgets. Canonical Status carries one typed domain error detail preserving code and bounded message. Native snapshots validate Any type, session, state/version/progress, timestamps, terminal results and immutable output descriptors.
- Canonical image records/content, explicit physical-Z relief mapping and sampled resolution diagnostics share one checked public domain contract. ProjectInfo and inspection carry only the sole metadata table; self-contained manufacturing provenance includes bounded canonical content. Projects image import/retrieval use typed standard native Operations, never pixels in status or JSON tunnels.
- `appearance` owns strict scalar color/evidence/palette/study/report records; `PreparedPalette` binds immutable sorted rows and cached canonical/evidence hashes once. Ranking must not reparse, serialize or rehash unchanged palettes. D65 colorimetry is unclamped; matching declared measured conditions/row lots is not independent physical qualification. ProjectInfo carries only report metadata; bounded typed report JSON is a checked ByteStream artifact, not an RPC tunnel. Complete traversal, assessed mismatch, relevant unknowns, output truncation and interrupted search remain distinct.
- Packed SPLT/SPLM/SPLS/SPLR layouts and frozen fixtures remain explicitly versioned and independently validated; never serialize Rust memory layouts. SPLR owns bounded packed admission and descriptor/record correspondence, not machine-program parsing or verification. Engine/shell ship together; no framing or cross-version negotiation.
- Keep bounded control dispatch/reply values inline; do not add per-call heap indirection solely to shrink enum variants. Local Clippy size expectations must name this allocation tradeoff and remain narrow; packed payloads and native hot-path allocation budgets are independent.
- Exercise contracts tests, generator drift and independent protocol decoder tests. Real native publication/durability remains the engine's responsibility; see [control](../../docs/protocol/control.md), [project](../../docs/protocol/project.md), [manufacturing](../../docs/protocol/manufacturing.md).
