# Storage rules

- PTAC is the sole project representation. Core owns strict project10 meaning and exact closed object-role membership, including role 6 material collections and role 7 bounded retained SPLA fields; core-ptac owns SQLite, hashes/chunks, leases, filesystem safety and publication. Analysis closure binds the captured source/case/assumptions/operator/assessment, not a Jobs reference. Invalid field semantics refuse without recomputation. Directory projects refuse without conversion or fallback.
- Validate source identity, enabled/disabled canonical image references/content, palette original/canonical semantics and accepted evidence, and complete manufacturing bundle framing/hash/input/content before project publication. Retain captured Arc allocations and existing per-domain/current/history/prepared budgets. Saved bytes are not native admission or independent program replay.
- Every load validates the independent typed recovery guard and applies its revision/all-allocator floors without changing saved revision or semantic dirty content. Validate other retained root counters when readable; damaged previous payload does not block valid current and damaged current never causes ordinary fallback. Explicit recovery allocates above durable/live floors and remains dirty. Recovery saves carry a private attachment/head/selected-root binding and retain the validated previous, never damaged current.
- Source load budgets govern additional allocated capacity, supplied by the engine rather than a Core RAM quota. Reused immutable source Arcs need no second allocation allowance, but every actual saved chunk/object is freshly stream-verified before sharing. A correct cache cannot conceal storage corruption or bypass cancellation.
- Normal saves freshly verify the admitted selected snapshot's exact bytes/closure without cloning its assets. Save As shares retained assets and charges any missing previous-root captures against remaining budgets. SaveStage::BeforeCommit is the late irreversible decision for existing COMMIT or new-target exclusive publication.
- Keep publication outcome separate from attempted manifest. Unconfirmed/unknown receipts attach ownership and force sticky uncertainty. Preserve the prior confirmed baseline only for the same attachment; an uncertain new target has no confirmed saved revision. Unknown writes require explicit inspect/reopen. Same-writer reopen retains its lease and does not erase Core uncertainty. Explicit collection/compact preserve semantic history and never replace the live file. See [storage contract](../../../../docs/protocol/project.md); deterministic tests are not platform/power-loss certification.
