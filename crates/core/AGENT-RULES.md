# Project authority rules

- Core alone owns persistent project transactions, monotonic revision/occurrence/surface-layer/process-layer/process-operation allocation, semantic dirty comparison and bounded session history. Dependencies are contracts, serialization, hashing and OS storage only; no kernel, runtime or UI.
- Snapshots share immutable captured source/manufacturing Vec allocations, checked canonical image assets, Arc-owned intent and Arc-owned ordered surface/process documents; geometry/history edits never deep-copy unchanged documents, rasters or printer/component data. Current/history/staged pins are bounded separately: 32 definitions/64 MiB source bytes, 64 MiB manufacturing allocated Vec capacity, 16 MiB surface allocated capacity, 16 MiB process allocated capacity and 4 MiB unique image Vec capacity, including incoming and live prepared candidates before releasing old state. Process documents admit at most64 layers/256 operations/64 KiB. Live images are at most16/1 MiB canonical bytes; surface metadata remains at most64 layers/32 KiB. History is at most64 transactions and occurrences at most256.
- Prepared edits are project/revision-bound and publish atomically. Save attaches a validated immutable checkpoint without clearing history. Read-only forbids mutation and saving.
- Appearance studies are independent Arc-owned authoring state. Palette admission retains exact original/canonical JSON and one immutable PreparedPalette owning validated sorted rows, canonical identity and cached evidence hashes; canonical identity keeps first-admission provenance across current, undo/redo and live prepared edits. A separate 64 MiB appearance allocation budget includes palette bytes, parsed documents, identity caches, study metadata and shared reports. Study-only edits preserve manufacturing bytes/input identity and never own scene revision. Explicit complete-report acceptance validates current palette/target/limits, evidence and selected alternative; every prepared candidate must fit both the complete serialized manifest and recovery envelope, reserving maximum revision/allocator digit growth.
- Explicit manufacturing intent, whole-face surface metadata, source-bound process intent and verified-worker artifact publication are prepared transactions. Geometry/intent/surface/process edits invalidate the active artifact atomically; undo restores coherent inputs/artifact without rewinding allocators. Process Reset clears all O1 contributions in the exact source scope, including disabled/erased layers, to reveal inheritance. SurfaceOverlays.images is the sole sorted metadata authority and exactly matches enabled and disabled image references plus the current immutable asset map. Atomic image admission searches retained current/undo/redo ownership and shares the complete first-admission record/allocation; saved metadata disagreements are corruption, not reimport normalization. Layer/target removal prunes only unreferenced current images. Occurrence deletion cascades its surface/process layers; final-definition deletion cascades definition layers. Core validates structural targets, canonical image content, bundle framing, exact-byte hash, record and complete semantic-input provenance/content table, never native face identity, plans or independently replayed programs. Core never decodes PNG, retains source image paths or depends on surface-fields.
- SetSparseFraction reuses only the exact-scope whole-volume winner; SetBoxSparseFraction reuses the exact-scope winning box and updates its bounds/value/explicit nullable permission. Otherwise each allocates one layer/operation. Authoring works before manufacturing intent exists without persisting a substitute global fraction. Repeated adjustments preserve IDs; history never rewinds allocators. Whole-volume status ignores box masks; spatial resolve uses half-open definition-local-mm bounds.
- JSON parsing preserves finite `f64` values exactly (`serde_json/float_roundtrip`): durable artifact summaries and committed records compare exactly. Do not weaken equality to hide serialization drift or silently re-pin changed totals.
- Storage guarantees and exact format are canonical in [project.md](../../docs/protocol/project.md); exercise `cargo test -p spiling-core` and actual engine crash/concurrency workflows. Tests do not establish power-loss/platform certification.
