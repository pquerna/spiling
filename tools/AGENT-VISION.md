# Tooling vision

A fresh contributor machine should obtain the pinned prerequisites, run the actual native architecture and reproduce packaged artifacts with one documented command surface. Tooling owns dependency provenance and release preparation, not geometry or planner behavior. The command surface exercises authenticated gRPC diagnostics, source-backed authoring, native geometry inspection and software-only manufacturing. Trusted TypeScript printer/recipe authoring produces bounded inert JSON for Rust validation, not an engine plugin runtime. Native target-directory overrides are honored, and builds default to one Cargo job; this is not a hard memory bound.

The manufacturing, planar/cylindrical-finish and spatial-image CEF scenarios exercise actual operator controls and the native bridge rather than an API echo or mocked panel, including durable native face/image intent and independently replayed derived material. Leading fixture cases validate the shared contract/data flow; they do not define special production geometry recognition. Owned Linux app data isolates durable history between smoke runs while preserving restart evidence within each run. Explicit startup-only no-GPU diagnostics permit software workflow evidence when physical WebGPU is unavailable, without claiming display/picking, dialog, machine, tactile or hardware certification.
