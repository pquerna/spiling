# Tooling rules

- Root commands are implemented in `run.mjs`; keep command failures fatal and preserve child exit status.
- Use Node 24 and pnpm 10.32.1, Rust 1.99.0 and committed lockfiles. Never silently substitute runtime/kernel/toolchain backends.
- Stage native sidecars using the Rust target triple and ship license/source/provenance notices. Regenerate the release notice directory without stale dependencies. Retain the native CEF archive's original LICENSE.txt and CREDITS.html as well as crate/npm license texts; the flattened upstream cache omits LICENSE.txt. Extract it once, stopping after the member with GNU tar `--occurrence=1` or Windows/macOS BSD tar `--fast-read`. Tool-managed artifacts stay ignored.
- Build operations must be portable across Windows, macOS and Linux; shell-specific acceptance runners are explicitly platform-labeled.
- Contract generation owns generated files. Check drift without rewriting output.
- Packaging compiles release without bundling, collects notices after CEF is available, then bundles the existing binaries. Do not require a debug bootstrap build just to package release.
- Exercise actual engine/CLI and packaged desktop commands. Refer to `docs/quality/B0-plan.md` for acceptance; report unexecuted platforms as unverified.
- `pnpm manufacturing:intent TRUSTED_SOURCE.ts NEW_INTENT.json` type-checks and executes a trusted TypeScript author module with operator permissions; it is not a sandbox. Emit bounded finite JSON without overwriting existing output. The engine independently validates inert intent and never executes the author module.
- Respect `CARGO_TARGET_DIR` when staging sidecars and locating CLI outputs. Default Cargo build jobs, Rust test threads, Rayon workers and the Go-backed TypeScript author's `GOMAXPROCS` to one, honoring explicit environment overrides. Resource-sensitive host verification additionally requires externally enforced memory/task limits and sequential native workloads; worker counts alone do not bound kernel/test memory.
- Desktop `--scenario manufacturing` drives the real production panel and Tauri adapter, including source admission, full intent, Core history/checkpoint/reopen, fresh report/motion and exclusive four-file export. `--scenario surface-finish` and `--scenario cylindrical-finish` add actual native face selection, durable finishes/history, original/added-material accounting and invalidation/read-only reopen. The cylinder case admits the unchanged independent full-face source by honest filename and compares native baseline versus actual finished paths/program, not only metadata. Fixture assumptions belong in the runner, never production admission. Optional no-GPU attachment requires explicit startup debug/root plus SPILING_MANUFACTURING_DIAGNOSTIC=1, and reports diagnostic-only/no-picking/no-hardware evidence. Never mock native manufacturing or weaken ordinary product WebGPU admission.
- Plain `--scenario manufacturing` alone accepts `--manufacturing-source RELATIVE_STEP` relative to the runner's cwd. Copy bytes unchanged under their honest basename into the owned fixture root and admit through native tokens, including explicitly labelled no-GPU controls. Exercise accepted bed-operation cancellation/ACK-winning completion without project/scene/pose mutation, then prepare afresh. Inspect original-source support/contact brackets and envelope before explicit Apply and Core Undo/Redo. Custom inputs use geometry invariants, not fixture-specific expected poses; built-in fixtures additionally check physical placement tolerance.
- `--scenario image-relief` and `image-relief-planar` add genuine PNG mapping, canonical preview, stored-image remapping without the source, varying-Z paths and fresh read-only replay/export. Compare independently sampled cylindrical native sections within their declared sampling certificate, never require bitwise geometry across different sample Z. Within a captured invariant slab, source accounting must remain separate from changing relief.
- Linux CEF smoke runs use an owned temporary `XDG_DATA_HOME`, preserving durable operations across restart inside that run without consuming or deleting the operator's bounded ledger. Remove only owned app data after desktop/engine closure; preserve it on uncertain live-writer failure.
